## Cómo retomar

1. Leer [`PREMISAS.md`](PREMISAS.md) y [`ARQUITECTURA.md`](ARQUITECTURA.md).
2. Leer este documento y la sección V3.94.2 de [`audit/PARKED.md`](audit/PARKED.md).
3. Verificar el árbol: `git status`, `git log -5 --oneline`, y desde `backend/`
   `python -m pytest -q`.
4. Trabajar en subagentes con instrucciones cerradas y revisar su diff antes de
   seguir. Si el contexto se satura, actualizar este documento antes de cortar.

## Proceso de release (invariantes)

- Rama `release/vX.Y.Z` desde `main`, PR y CI 12/12 sobre el commit de release.
- El **tag anotado se crea después del verde**, nunca antes. Después: fast-forward
  de `main`, push del tag y GitHub Release (no *draft*, no *prerelease*) con
  `gh release create vX.Y.Z --notes-file docs/releases/release-notes-vX.Y.Z.md`.
- Un commit `docs(audit)` posterior registra el estado de publicación aquí y en
  `PARKED.md`. La rama de release se conserva para la auditoría.
- No se bumpean `GENERATOR_VERSION`, `DECISION_POLICY_VERSION`,
  `CURRICULUM_VERSION` ni `LISTENING_BANK_VERSION` sin decisión explícita.
- Los cambios de mantenimiento sin efecto en producto (documentación, código
  muerto) van en rama `chore/...` con PR y CI verde, sin bump ni tag.

## Siguiente paso: telemetría real

V3.95 (`sense_id` estable y sentido nuevo pedagógico) espera a datos. La fila del
ledger solo nace al **fallar una frase de Listening que contiene una palabra con
carta en el léxico**.

1. Guardar palabras polisémicas en el léxico (desde el diccionario) y hacer
   ejercicios de Listening hasta fallar frases que las contengan.
2. `python scripts/sense_shadow_report.py` para las cuentas
   (`possible_mismatch`, `occurrence_split`, reparto de razones).
3. `python scripts/sense_shadow_report.py --examples 10` para ver la frase de cada
   `gloss:other`, `role:other`, `gloss:other:weak` y `occurrence:split`.

**Criterio para abrir V3.95** (declarado y revisable): al menos 30 filas con
veredicto, y revisión humana de todos los ejemplos `gloss:other` y `role:other`.
Si la mayoría de los `mismatch` probados son falsos positivos, V3.95 empieza por
las glosas, no por el `sense_id`. El P1 de dos `mismatch` hacia sentidos distintos
entra en V3.95 con su propia política (ver `PARKED.md §V3.94.2`).
